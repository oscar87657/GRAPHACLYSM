# 경제 연결 이후의 성좌 개편 · 다음 작업 기준

사용자는 우선 경제/상점/콘텐츠 반복/조준 UX를 수정하고, 이후 성좌 개편으로 이어가기를 요청했다. 이 문서는 다음 구현의 준비 자료이지 아래 기능의 완료 보고가 아니다.

## 실제 문제

현재240개 카탈로그의 대부분은 선행 조건·가격·설명만 있고 전투 해석기가 없다. 장착 슬롯을 기존 전투 형태에 연결했던12개 `PrototypePartial` 정의도 새 집행/기록/조율/관측 명령에서는 일부만 사용된다. 미지원 표시를 단순히 없애거나 모든 노드에 피해+1을 붙이는 것은 사용자가 원한 ‘행동 방식이 바뀌는 나무’가 아니다.

현재 새 방식에서 연결된 고유 ID는 핵심4, 조건부 특성3, 기존 궁극기6이다. 기본 전투 방식은 시작 선택으로 이미 사용할 수 있으므로, 같은 핵심에 다시 점수를 쓰는 것이 실제로 어떤 변화인지도 정리해야 한다. 기존 전투 기술 형태6개는 별도 legacy 명령에서만 작동한다. `GrowthRuntimeSupport`의 표시가 이 차이를 반영한다.

## 다음 구현 순서

1. 유효 선행 경로부터 재편한다. 구현 대기 노드를 통행료로 사야만 작동하는 특성에 도달하는 구조를 없앤다. 실제 효과가 있는 시작 노드/연결을 만들고, 시작 선택으로 이미 가진 능력은 중복 강화로 오해하지 않게 한다.
2. 큰 나무 하나를 유지한다. 아래→위, 비대칭, 전투 변화의 크기와 실제 연계를 기준으로 섞는다. 스킬/궁극기/공통의 독립 화면이나 허브별 나무로 되돌리지 않는다. 전후 비교·체험·검색·개별 해제·카메라 보존은 유지한다.
3. 초반부터 완성된 행동을 주는 분기를 먼저 연결한다. 집행의 파열 소비, 기록의 위치/발동 시점, 조율의 회전/견인, 관측의 원점/자가 강화처럼 실제 전투 판단이 달라져야 한다. 수치만 다른 가지를 채우는 작업으로 대체하지 않는다.
4. 단순하다는 피드백이 남은 궁극기를 같은 과정에 포함한다. 시작/장착/특성/궁극기/재현 사건을 분리하고, 한 번의 강한 연계는 허용하되 자기 재귀만 막는다. 미구현 궁극기에 가짜 시연을 만들지 않는다.
5. 검증한 규칙을 공통·혼합 노드로 확장한다. 카드=도형 재료, 성좌=사용 규칙, 유물=원정의 예외, 영구 성장=출발 선택이라는 역할을 유지한다. 상점의 유물/성장점 구매와 연구권 수입을 포함해 예산과 성장 시점을 다시 평가한다.

## 구현 계약과 완료 판단

- 각 고유 효과에 실제 Core 해석기, 미리보기와 실행 일치 검사, 비용/쿨타임/발동 횟수 검사, 저장 재생 회귀가 있어야 ‘전투 효과’로 표시한다.
- acquired/equipped/active runtime rule을 섞지 않는다. 조건부 노드는 어떤 시작 방식/장착 상태에서 적용되는지 상세와 전투 결과에 표시한다.
- 실행 불가능한 노드는 원정 구매 경로에서 분리하되, 큰 나무의 향후 확장 자료 자체를 삭제할지는 사용자와 현재 트리 개편 범위에 맞춰 결정한다. 기존 투자/저장 데이터는 유지·환급·이행 중 명시적 정책을 정한다.
- 기존26 이하 저널을 새 가격/선행/전투 효과로 재생하지 않는다. 안정 ID와 새 opt-in 규칙 또는 검증된 이행을 사용한다.
- 같은 전장/비슷한 손패에서 ‘이 노드 때문에 어느 위치·카드 순서·방출 시점을 바꿨는가’를 확인한다. 표본/출력 수치·화면 검사가 통과해도 재미와 전체 승률은 사람의 플레이로 확인해야 한다.
