# 대형 변형 성좌 기반 v16

2026-09-12. `GRAPHACLYSM_성좌_240노드.json`과 `GRAPHACLYSM_대형변형성좌_기획안.md`를 실제 프로젝트의 성장 카탈로그·획득·장착·저장 기반에 연결한 첫 구현 단계다.

현재 배치와 진입 조건은 [아래→위 단일 트리 v17](ASCENDING_GROWTH_V17.md)으로 교체됐다. 아래 v16 허브·배치·저장 규칙은 이전 구현 기록이다.

## 이번에 연결된 범위

- 고유 ID 240개를 불변 `GrowthCatalog`로 편입한다. 공통 48개와 캐릭터 전용 96개를 합쳐 이안·루나가 각각 144개에 접근한다.
- 시작 6점, 방 완료마다 1점, 1·2층 보스 추가 3점으로 최종 보스 전 총 35점을 얻는다. 경험치·레벨을 거치는 원정 성장은 제거했다.
- `RunGrowthState`는 획득과 장착을 별도 배열로 관리한다. 핵심 능력 1개, 서로 다른 기술군의 전투 기술 2개, 궁극기 1개와 그룹별 특성 제한을 검사한다.
- 전투 시작 시 `CompiledGrowthBuild`가 획득 ID와 장착 ID를 불변 스냅샷으로 고정해 `BattleSkillLoadout`에 전달한다. 이후 지도 재배분은 이미 시작한 전투를 바꾸지 않는다.
- `requires_all`, `requires_at_least`, 국소 배타 그룹, 특성 장착 한도를 Core에서 판정한다. 기술 각성은 해당 세 특성 중 둘을 요구한다.
- 지도와 휴식 방에서 전체 재배분할 수 있다. 이미 얻은 성장점은 모두 돌려받으며 새 원정에서는 초기화된다.
- 저장 명령은 카탈로그 배열 위치가 아니라 문자열 ID의 결정적 해시를 기록한다. 240개 전체에서 충돌 여부를 시작 시 검증한다. 저장 형식은 2, 규칙 버전은 16이다.
- 기존 고정 18개 노드 화면은 탭이나 별도 트리 없이 144개 전체가 이어진 단일 대성좌로 바뀌었다. 기억의 핵에서 공통 규칙과 캐릭터 능력이 갈라지고, 전투 기술·궁극기·혼합 성좌까지 실제 선행 관계가 한 연결망을 이룬다. 내부 14개 section은 가지 배치용 데이터일 뿐 화면을 분리하지 않는다.
- 대성좌는 화면보다 큰 5750×4000 논리 월드에 놓인다. 마우스 드래그로 이동하고 휠 또는 상단 버튼으로 16~130% 확대·축소하며, 전체 보기와 선택 노드 초점 이동을 제공한다. 선과 노드는 뷰포트에서 잘라 상세 패널이나 헤더를 침범하지 않는다.

## 기획 데이터와 생성

루트의 `GRAPHACLYSM_성좌_240노드.json`이 기획 원본이다. 다음 명령으로 빌드에 포함되는 카탈로그를 재생성한다.

```powershell
& .\Tools\GenerateGrowthCatalog.ps1
```

생성 결과는 `Assets/Scripts/Core/Runs/GrowthCatalog.Generated.cs`다. 생성기는 노드 수가 240개인지 먼저 검사한다. 런타임 카탈로그는 ID 중복, 저장 키 충돌, 누락 선행 ID, 캐릭터별 144개 구성을 다시 검사한다.

## 현재 전투 연결 범위

이번 단계는 240개 효과를 전부 구현한 완료본이 아니다. 데이터·성장 규칙·로드아웃·저장·탐색 UI를 먼저 교체했다.

- v15에서 이미 동작하던 이안 `삼중 유리길/집행의 직선/거울 교환`, 루나 `만월 착지/초승달 회귀/별무리 전이`의 기본 행동은 `부분 구현`으로 표시한다.
- 기존 궁극기와 직접 대응하는 이안 `성좌 붕괴/불멸의 기록/흑경 반전`, 루나 `만월의 포옹/그믐의 칼날/월식 정지`도 `부분 구현`이다.
- 새 핵심 능력, 두 번째·세 번째 기술군, 공통 규칙 변형, 각성, 혼합 성좌와 새 궁극기 형태는 `설계 등록`으로 표시한다. 획득·장착·저장은 되지만 아직 전투 결과를 바꾸지 않는다.
- JSON의 새 설명이 기존 v15 동작과 다른 부분까지 구현된 것으로 간주하지 않는다. 다음 단계부터 `PlotPlan`과 효과 해석 계층을 만든 뒤 기술군 단위로 연결한다.

## 검증

Unity 6000.3.23f1 격리 사본에서 EditMode **156/156**을 통과했다. Full HD/720p 화면 fixture **35장**, 게임 Runtime errors **0**을 확인했다. 새 회귀는 240/144 카탈로그 수, 6점 시작, 선행·배타·2-of-3 각성, 전투 기술 2슬롯과 기술군 중복 금지, 재배분, 안정 ID 저장 재생을 검사한다.

로그는 `Logs/editmode-great-constellation-v16.xml`, `Logs/editmode-great-constellation-v16.log`, `Logs/great-constellation-v16-smoke-dotted.log`이며 캡처는 검증 사본의 `Logs/BasicsV9Captures`다. 화면 실행 중 Unity SearchDatabase 내부 예외는 게임 진입 전 Editor 서비스 오류로, fixture의 게임 Runtime 오류 집계에는 포함되지 않는다. Windows 빌드, 물리 마우스 수동 플레이, 전체 3층 밸런스와 Profiler는 이번 단계에서 검증하지 않았다.
