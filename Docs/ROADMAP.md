# GRAPHACLYSM 개발 로드맵

상태: **후속 개발 방향 정리 / 기능 구현 전**

개발 순서는 **UI·편의성·미감 정리 → 스토리 완성 및 연동 → 무한 등반과 밸런스 개편**입니다. 이 문서는 사용자와 정리한 후속 작업의 기준이며, 과거 기획서의 미완료 항목을 자동으로 모두 구현하라는 뜻은 아닙니다. 현재 구현은 [v42 체크포인트](PROJECT_CHECKPOINT_V42.md), 저장소 안내는 [README](../README.md)에서 확인합니다.

## 1. UI·편의성·미감 전면 정리

**우선순위: 다음 작업.** 개발용 화면의 흔적을 걷어내고 필요한 정보와 행동이 잘 보이도록 만듭니다.

### 작업 목록

- 메인·캐릭터 선택·지도·전투·보상·상점·성장·사전·설정 화면을 훑어 삭제/이동/통합/도움말 전환 대상을 정리합니다.
- 불필요한 문구, 중복 설명, 과거 규칙을 설명하는 문구와 개발자용 표현을 정리합니다.
- 튜토리얼과 도움말을 필요한 위치의 작은 `?` 아이콘으로 연결하고 언제든 다시 확인할 수 있게 구성합니다.
- 항상 보여야 하는 전투·진행 정보와 필요할 때 펼쳐보는 설명을 구분합니다. 중요한 정보까지 무조건 숨기지 않습니다.
- 버튼의 필요성·위치·크기를 검토하고 삭제·통합·재배치합니다.
- 글자 크기·여백·색상·패널·아이콘 표현을 통일하고, 클릭·드래그·스크롤·팝업 닫기의 일관성과 오입력을 점검합니다.

### 완료 기준

- 새 플레이어가 다음 행동과 필요한 도움말의 위치를 찾을 수 있습니다.
- 개발 흔적과 중복 설명을 정리하면서도 전투 판단에 필요한 정보는 남아 있습니다.
- 주요 화면을 1080p/720p에서 확인하고, 버튼·팝업·드래그의 겹침과 오입력을 검사합니다.
- 기능 삭제 여부와 화면 개편 결과를 사용자 플레이 피드백으로 확인합니다.

## 2. 스토리 완성 → 게임 연동 → 용어 재편

**우선순위: UI 정리 이후.** 탑을 오르는 이유와 캐릭터의 전투·성장이 하나의 이야기로 이어지도록 합니다.

### 작업 목록

- 세계관, 캐릭터의 목적과 관계, 전체 사건 흐름과 결말을 먼저 설계합니다.
- 이야기의 흐름을 확정한 뒤 층·보스·이벤트·유물·대사와 실제 진행에 연결합니다.
- 스토리에 맞춰 고유명사와 시스템 용어를 정리하고 카드·유물·노드·키워드·도움말의 표현을 맞춥니다.
- 반복 플레이에서의 대사 생략·재확인, 이야기 진행과 저장·이어하기를 함께 설계합니다.

### 검토 중인 구상

**히든 엔딩을 만들고, 클리어 보상으로 각 캐릭터의 세 번째 전투 스타일을 해금하는 방안**을 검토합니다. 현재 구현된 기능이나 확정된 해금 규칙은 아닙니다.

엔딩의 진입·클리어 조건, 해금 범위, 세 번째 스타일의 능력과 성장 경로는 스토리를 설계하면서 사용자와 확정합니다. 지금 임의의 설정·수치·일정을 추가하지 않습니다.

### 완료 기준

- 전체 이야기와 결말까지의 흐름이 정리되고, 각 장면이 어떤 플레이와 진행 상태에 연결되는지 명확합니다.
- 선택과 이야기 진행이 저장·이어하기·반복 플레이에서 일관되게 유지됩니다.
- 같은 개념의 명칭과 설명이 화면마다 달라지지 않습니다.
- 히든 엔딩과 스타일 해금은 채택 여부와 구체적인 조건을 확정한 뒤 구현·검증합니다.

## 3. 무한 등반 모드 + 레벨 디자인·밸런스 개편

**우선순위: 스토리 단계 이후.** 층수만 늘리는 것이 아니라 계속 다른 판단과 도전을 요구하는 등반 콘텐츠를 만듭니다.

### 작업 목록

- 끝없이 이어지는 층과 방·적·보스의 구성 및 등장 흐름을 설계합니다.
- 장기 등반에서 성장·보상·회복·자원 소모가 어떻게 이어질지 정합니다.
- 레벨 디자인과 함께 카드·유물의 효과와 조합을 재검토합니다.
- 지나치게 강한 반복 조합, 선택할 이유가 없는 효과, 전투가 늘어지는 구간을 점검합니다.
- 장시간 플레이의 저장·이어하기와 성능을 검증합니다.

### 완료 기준

- 등반 구간별로 새로운 판단이 생기고 난이도와 보상 변화에 설계 근거가 있습니다.
- 카드·유물의 변경이 일반 원정과 무한 등반에 주는 영향을 각각 확인합니다.
- 장시간 등반에서도 진행·자원·저장이 안정적으로 유지됩니다.

무한모드의 진입 조건, 성장 상한, 종료·정산 방식, 난이도 상승 수치는 이 단계의 상세 기획에서 결정합니다. 먼저 층만 늘려놓고 수치 조정으로 끝내지 않습니다.

## 단계 사이의 원칙

- UI 단계에서는 가독성과 조작을 먼저 정리하고, 세계관에 따른 최종 명칭은 스토리 단계에서 확정합니다.
- 무한 등반의 레벨 디자인과 카드·유물 효과 개편은 함께 진행합니다.
- 문서에 적었다는 이유로 구현 완료로 표시하지 않습니다. 실제 구현과 검증 후 상태를 갱신합니다.
- 각 단계에 착수할 때 사용자의 추가 요구와 미정 사항을 확인합니다. 이번 문서화에서는 코드·저장·밸런스를 바꾸지 않습니다.
