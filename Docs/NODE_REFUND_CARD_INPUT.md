# 개별 노드 해제·겹친 카드 입력 수정

2026-09-12 · v19 후속 수정.

## 노드 해제

지도/휴식에서 습득한 노드를 클릭하고 `노드 해제 · N점 반환`을 누른다. 비용 전액을 반환하고 해당 노드의 장착을 해제한다. 나머지 노드는 유지한다. 원정 숙련은 남은 투자량에서 다시 계산한다.

다른 습득 노드의 진입 경로, 필수 선행, N개 이상 선행, 누적 투자 문턱이 깨지는 경우 해제를 막고 영향을 받는 노드 이름을 표시한다. 후속 노드부터 해제하거나 전체 재배분을 사용할 수 있다. 여러 OR 진입 중 하나만 없어져도 대체 경로가 남으면 통과한다. 자동 연쇄 삭제는 하지 않는다.

`RunGrowthState`가 가능 여부와 반환을, Application이 지도/휴식 제한과 저장을 소유한다. 검사는 고정된 상태 배열을 잠시 검사한 뒤 finally에서 복구하며 새 배열을 만들지 않는다. 성공 명령만 안정 노드 ID로 기록한다.

## 카드 클릭

기존에는 뒤에서 앞으로 그림을 그리는 순서대로 각 카드의 GUI.Button도 먼저 실행됐다. 호버 판정은 올라온 카드가 아니라 원래 부채꼴 위치를 검사했다. 따라서 앞 카드가 보이는 영역에서 뒤 카드가 입력을 가져갈 수 있었다.

이제 카드 그리기와 입력을 분리한다. 확대 상세/들어 올린 카드부터 검사하고, 나머지는 실제 그리기의 역순으로 검사한다. 마우스를 누른 카드와 뗀 카드가 같을 때 한 장만 사용한다. 다른 카드로 드래그하거나 손패 수가 바뀌면 사용하지 않는다. 마우스 다운에서 확정하지 않는다. 상세로 이동하는 호버 통로는 설명만 유지하며 카드 사용 영역이 아니다.

View는 누른 카드 인덱스/손패 수 두 정수만 추가 보관한다. 카드 사용 규칙이나 수학 판정은 변경하지 않는다.

## 저장과 검증

기존 명령의 의미·ID·생성 수치가 바뀌지 않으므로 형식 2/규칙 19를 유지한다. 새 RefundGrowth 명령은 enum 끝에 추가했다. 기존 v19 원정을 계속 불러올 수 있다. 새 해제 명령이 들어간 저장을 이전 실행 파일에서 여는 역방향 호환은 지원하지 않는다. 사용자 저장을 테스트에 사용하거나 삭제하지 않았다.

EditMode 180/180 통과, 화면 fixture 43장·게임 Runtime errors 0. 반환·재구매·장착 해제·선행/투자 보호·전투 중 거부·저장 인코딩/재생을 확인했다. 입력 화면 회귀는 겹친 카드/확대 카드 우선 판정, 누름·뗌으로 실제 카드 ID 사용, 다른 카드에서 놓을 때 취소를 검사한다. 전체 수동 플레이 검증과는 구분한다. 로그는 `Logs/editmode-refund-card-input.xml`, `Logs/refund-card-input-smoke.log`다. 게임 시작 전 Unity SearchDatabase 예외는 Editor 서비스 오류로 별도 기록됐다.

전투 개선은 [별도 기획](COMBAT_ENGAGEMENT_PROPOSAL.md)만 작성했으며 신규 전투 규칙을 적용하지 않았다.
