# 성장 UX 추가 기획 — 1차 구현

2026-09-12. 사용자 승인 범위는 성장 UX 패키지 전체지만 이 기록은 첫 구현 단위의 완료/미완료를 구분한다. 앞선 전투 개편 P0/P1을 대체하거나 완료 처리하지 않는다.

## 유지한 기준

- 종류별 군집이나 별도 트리를 만들지 않았다. 혼합형 아래→위 단일 나무의 좌표·연결·5단계 투자 조건을 그대로 사용한다.
- 고유 240개/캐릭터당 144개, 성장 비용, 초기 예산, 전투 효과와 저장 형식 2/규칙 21을 유지했다. 이전 v21 원정 재생 가능. 영구 저장 형식도 1 그대로다.
- 출발 경험 필드는 이미 시작 성장점으로 쓰이고 있다. 이번에는 구매 설명과 현재 효과를 일치시키고 수치를 바꾸지 않았다. 제안의 효과 종료/환급 정책 이행은 아직 하지 않았다.

## 구현

### 기능명과 검색 — U2 일부

사용자가 제공한 `data/node_ui_catalog.proposal.json`의 240개 ID/기능명/요약/symbolId를 `GrowthUiCatalog.Generated.cs`로 매핑했다. 기존 이름은 상세에 보존한다. 부분 구현 기술은 기존 실제 기술 설명을 유지하고, 나머지 새 요약에는 ‘설계 설명 · 아직 작동하지 않음’을 명시한다. 이를 실제 전투 효과 또는 효과 수치 바인딩 완료로 보지 않는다.

`GrowthCurrentTitle`은 부분 구현 12형태의 기능명도 실제 v21 동작에 맞춘다. 예를 들어 불멸의 기록을 아직 없는 ‘도안 반복’으로 표시하지 않고 ‘그래프 강화·적 이동 봉쇄’로 표시한다. writing-studio 검토 기준을 적용해 고유 이름과 실제 기능을 분리하고 미래 효과를 현재 능력처럼 쓰지 않았다.

상단 검색은 이름·기능명·효과·현재 설명·분류를 찾는다. 쿨타임/대기시간을 재사용으로 연결한다. 일치하지 않는 노드는 어둡게 남겨 기존 연결 경로를 보존한다. 이전/다음은 해당 노드로 이동하고 클릭 고정 상세를 연다. 검색 중 G/D 등 게임 단축키가 입력을 가로채지 않는다. 검색 판정은 문자열 변경 또는 원정 교체 때 캐시한다.

### 선행 계획 — U1 계산/비교 일부

하단 ‘선택 노드의 선행 경로 계획’으로 ALL·진입 OR·N-of 조건을 확장한다. 공유 선행은 집합으로 한 번 계산하고 이미 보유한 것은 제외한다. 후보를 복사한 성장 상태에서 검사해 투자 게이트/배타 조건이 막히면 표시한다. 관계없는 투자 채우기 노드를 임의로 추가하지 않는다. 미구현 노드 개수와 포인트 부족도 표시한다.

10,000번의 확장/집합 결합 상한에 닿으면 부분 결과를 최저 비용으로 보여주지 않고 가까운 선행 선택을 요청한다. 선택 시에만 계산하며 프레임마다 실행하지 않는다. 이는 현재 카탈로그용 계산기로 임의 손상된 외부 카탈로그·과거 rank 원장을 지원하는 범용 완성 계획기가 아니다.

**경로 창은 읽기 전용이다. 일괄 결제·분기 확정·계획 영구 저장은 아직 미구현**이다. 현재 원정 시작 경로 자체에 미구현 노드가 있어 미지원 판매 차단만 넣으면 트리 전체를 잠그게 된다. 이 전환과 stable ID 배치 명령/복구를 다음 단위에서 함께 해결해야 한다. 기존 개발용 단일 습득은 변경하지 않았다.

### 기록 보관소 — U3 표시/묶음 구매

기능명·현재/목표 누적 효과·단계별 합산 비용을 표시한다. +/-는 목표만 편집한다. 구매 내역 확인→구매 확정 두 단계이고 부족하면 아무것도 결제하지 않는다. 감소는 미구매 예약만 취소하며 기존 단계를 환급하지 않는다. 구매 목록을 취소하고 닫는 버튼을 제공하고, 미확정 목록이 있을 때 Esc로 조용히 사라지지 않는다.

`LegacyProgression.TryPurchaseRanks`는 예상 잔액/rank를 확인하고 후보 계정을 생성한다. 후보 저장 성공 후에만 현재 계정을 채택한다. 저장 실패/오래된 견적/중복 확정은 차감하지 않는다. 기존 정산 seed 이력과 영구 단계는 유지한다. 손상/미지원 형식 파일을 읽은 상태는 읽기 전용으로 구매·정산·저장을 막아 0잔광 파일로 덮어쓰지 않는다. 자동 백업 복구 UI는 아직 없다.
