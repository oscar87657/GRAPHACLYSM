# 전투 대응 실험 v20

2026-09-12. 전투 재미 기획의 첫 단계인 적 세 종류와 조합 전투를 구현했다. 빌드 3종·잔선·카드 보존·전멸 외 목표는 아직 구현하지 않았다.

## 어디에서 플레이하는가

새 원정의 1층 일반/정예 전투에서 다음 세 조합이 나온다. 같은 조합은 같은 적 위치와 지형을 사용하므로 대응 차이를 비교하기 쉽다. 덱과 손패는 정상 원정 규칙을 따른다.

| 전투 | 적 조합 | 먼저 비교할 선택 |
| --- | --- | --- |
| 사선과 봉인 | 선형 포수 + 봉인 서기관 | 사선을 피하면서 프리즘 봉인을 끊을 것인가, 서기관부터 처치할 것인가 |
| 끊어야 할 연결 | 선형 포수 + 연결 수호자 | 보호받는 포수에게 공격을 집중할 것인가, 수호자/매듭을 동시에 맞힐 것인가 |
| 봉인된 매듭 | 연결 수호자 + 봉인 서기관 | 이동·프리즘을 확보할 것인가, 보호 연결을 먼저 끊을 것인가 |

일반 적 체력은 24/26, 공격 3. 정예는 32/34, 공격 4. 두 적은 (2,1)/(8,1), 프리즘은 (5,0), 일회용 보호 기점은 (2,-0.7)이다. 기존 고체 기둥은 이 세 실험 전투에서 제외했다. 1층 보스와 2·3층은 기존 생성 전투를 유지한다. 이번에 전체 원정 밸런스가 완성됐다고 보지 않는다.

## 실제 규칙

### 선형 포수

턴 시작에 적 위치에서 플레이어 조준점을 향해 전장 끝까지 선을 고정한다. 공격 반폭은 0.32이고 실제 적중은 플레이어 반경을 더한 선분 거리로 검사한다. 움직인 뒤 다시 조준하지 않는다. 선을 따라 뒤로 이동해도 공격을 받지만 옆으로 벗어나면 피한다. 판정의 양 끝 둥근 부분과 경계선을 화면에도 표시한다. 기둥을 엄폐물로 삼는 규칙은 추가하지 않았다.

### 봉인 서기관

홀수 턴에는 프리즘 위치를 봉인할 것을 예고한다. 프리즘이 없으면 적과 턴 시작 플레이어의 중간 지점을 제한된 좌표로 선택한다. 해당 턴에는 일반 공격이나 축적 보호막 12를 얻지 않는다. 예고가 끊기지 않으면 다음 계획 턴 한 번 동안 반경 0.9 구역으로 이동할 수 없고 구역 안 프리즘도 막힌다. 짝수 턴에는 일반 원형 공격을 한다.

실제 그래프가 반경 0.35의 중앙 표식을 맞히면 예고를 취소하거나 이미 활성화된 봉인을 해제한다. 미리보기·응축만으로는 끊기지 않는다. 활성 봉인을 끊는 그래프는 그 방출에서 프리즘을 사용할 수 있다. 현재 봉인 안에 서 있는 플레이어를 강제 이동시키지는 않으며 밖으로 나갈 수 있다. 서기관 사망 시 남은 봉인은 사라진다.

### 연결 수호자

매 턴 살아 있는 다른 적 하나를 연결한다. 연결 아군이 받는 **그래프 직접 피해만 4 감소**하며 최소 피해 1은 유지한다. 다른 수호자와 중첩되지 않는다. 기술·잔불·지형 피해를 줄이지 않는다.

같은 그래프로 수호자 본체와 연결선 중앙의 반경 0.3 매듭을 모두 맞히면 그 방출부터 보호를 해제한다. 단순히 선 끝을 스치는 것과 구분하기 위해 중앙 매듭을 명시했다. 다음 턴 살아 있으면 다시 연결하고, 혼자 남으면 연결하지 않는다. 방출의 주 피해는 적 처치/상태 적용 전에 고정해 배열 처리 순서로 예상 피해가 달라지지 않도록 했다. 매듭을 끊지 않은 방출에서 수호자가 죽더라도 그 방출의 주 피해는 미리 본 값대로 처리되고 이후 보호는 사라진다.

## 표시와 소유권

직선 공격·봉인 구역/중앙 표식·보호 연결/중앙 매듭을 항상 보여 준다. 지금 조립한 그래프로 끊을 수 있으면 청록색과 `방출하면 해제` 문구로 바뀐다. 단순 색상에만 의존하지 않는다. 적 이름 호버에는 해당 규칙과 예외를 설명한다. 새 자원 바나 별도 전투 메뉴는 추가하지 않았다.

`EnemyState`는 고정 사선 끝점, 봉인 좌표/만료/중단, 보호 대상/해제 상태를 가진다. `BattleThreats`는 미리보기·봉인·보호 판정, `BattleSession`은 행동 순서와 피해 적용을 소유한다. `GraphaclysmThreatView`는 Core 좌표/반경/해제 여부로 그린다. 추가 배열은 전투 Reset 시 적 수만큼 만드는 피해 스냅샷 하나다. 핫 루프에 임시 컬렉션을 추가하지 않았다. 전체 렌더링 성능은 Profiler로 재검증하지 않았다.

## 저장과 검증

생성 전투·판정이 바뀌므로 저장 형식 2/규칙 20으로 올렸다. 새 원정이 필요하다. v19 저장 파일은 삭제하지 않았고 설정·영구 기록도 유지한다. 새 별도 명령 없이 기존 카드·이동·방출·적 행동 명령으로 위 상태를 재생한다.

최종 EditMode 194/194 통과. 사선 회피/실피해, 봉인 예고·해제·만료·응축, 보호 해제/유지의 예상·실제 피해, 적 처리 순서, 저장 재생을 검사했다. 화면 fixture 48장·게임 Runtime errors 0이며 새 세 조합, 활성 봉인, 720p를 포함한다. 실제 사용자 저장은 테스트에 사용하지 않았다. 게임 시작 전 Unity SearchDatabase 내부 예외는 Editor 서비스 오류로 별도 기록했다.

로그: `Logs/editmode-threat-v20.xml`, `Logs/threat-v20-smoke.log`. 대표 화면: [포수+수호자](Screenshots/threat-link-v20.png), [활성 봉인](Screenshots/threat-seal-v20.png).

수동 전체 원정·새 실행 파일 빌드·재미 개선 측정은 아직 하지 않았다. 시험할 질문은 세 가지다: 적 조합에 따라 먼저 처리할 적이 바뀌는가, 이동 방향이 달라지는가, 봉인/매듭을 끊으려고 다른 식을 만들게 되는가. 이 차이가 약하면 새 콘텐츠를 늘리기 전에 세 전투의 배치와 규칙을 조정한다.
