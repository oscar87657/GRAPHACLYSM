# GRAPHACLYSM 에이전트 작업 지침

프로젝트 전체에 적용한다. 작업 전에 이 문서와 루트 기획·구조 문서를 읽는다. 현재 코드와 최신 사용자 요청이 문서보다 우선한다. 기능 변경 시 문서도 같은 작업에서 갱신한다.

## 프로젝트와 방향

- Unity 6000.3.23f1, Windows PowerShell. 현재 Git 저장소가 아니다.
- 한국어로 소통하고 결과·다음 확인 사항을 간결하게 알린다.
- 핵심은 작은 수식 조각을 조립하여 적을 맞히고, 같은 필드의 자신을 맞혀 버프를 받는 덱 빌딩 로그라이트다.
- 캐릭터는 이안과 흰머리 동생 루나. 과거의 아르카·노아 이름을 새 콘텐츠에 사용하지 않는다.
- 아트는 아르케아의 빛·파편·여백을 중심으로, 리버스 1999의 재료감·회화적 명암을 참고한다. 공식 게임 이미지는 조사 자료로만 두며 런타임 자산으로 넣지 않는다.
- 새 v2 생성 초상·배경은 프로토타입 시안이다. 사용자의 이안 참고 원본을 덮어쓰지 않는다. 최종 도트 제작 등 납품 형태는 별도 결정 사항이다.
- 이전 지침·기획·아트는 `Docs/Archive/BeforeCombatV2`와 `Logs/BeforeCombatV2-20260906`에 보관되어 있으며 현재 요구를 대체하지 않는다.

## 의존성과 소유권

`Runtime/Presentation → Application → Core`를 지킨다. Core는 Unity API를 참조하지 않는다. 콘텐츠 정의는 불변이며 체력·에너지·좌표·상태를 화면이 직접 수정하지 않는다. 상태 변경은 Try 명령 또는 명시적 전이를 통한다. 전역 변경 가능 싱글턴을 추가하지 않는다. 조립 루트는 Bootstrap이다.

BattleSession은 수식·적·TacticalCombatState를 소유한다. 플레이어 좌표·공명·궁극기는 TacticalCombatState, 상태 수치와 수명은 CombatStatusState가 가진다. RunGameSession은 손패와 수식의 트랜잭션, 맵·보상·지속 체력·공명을 조정한다. 진단용 상태 설치는 Editor 전용으로 제한한다.

## 현재 규칙

- 타이틀 → 이안/루나 → 3층 분기 맵 → 전투 → 카드/정예 유물 → 완주/패배.
- 실제 카드 풀은 `SpellCardCatalog` 18종. 입력 2, 연산 5, 계수 5, 각인 4, 유틸 2.
- 시작 덱은 ID로 구성된 14장, 기본 손패 6장. 입력 부족으로 작도가 불가능한 손패를 방지한다.
- 입력 1개 + 연산·계수 최대 8개 + 각인·유틸 최대 2개. 조립 연산은 반복 가능하고 동일 각인은 중복 불가.
- 수식과 손패의 이력 버퍼는 `BattleSession.MaximumPlayedCards`(11)를 사용한다. 상수 9로 되돌리지 않는다.
- 플레이어 초기 (4,-2), 반경 0.48, 상하좌우 1.5 이동을 턴당 한 번, 비용 1 EN. 카드 취소로 이동 비용을 환급하지 않는다.
- 자기 그래프 적중은 기본 보호막 3 + 각인 효과. 적·자신 모두 한 작도에 대상당 한 번 처리한다.
- 보호막·집중·재생·잔불·약화·노출·고정·경쾌. 고정 크기 8 배열, 수치 상한 24. 집중·노출의 새 적용은 이번 피해를 소급 변경하지 않는다.
- 적 조준점은 턴 시작의 플레이어 좌표에 고정된다. 일반 반경 0.85, 맹공 1.65. 축적 턴 보호막 12, 체력 피해를 준 일반 공격은 약화, 맹공은 잔불을 준다.
- 공명 최대 6, 작도 +1, 적·자신 동시 적중 추가 +1. 준비 취소 가능, 실제 작도에 소비, 전투 사이 유지.
- 이안 궁극기 피해 +6·이번 적 이동 봉쇄. 루나 궁극기 자신 적중 반경 1·자가 적중 시 추가 정화/보호막 8/회복 5.
- 직접 피해와 잔불 승리 모두 공통 CompleteVictory로 보상·맵을 진행한다.
- 등급 한국어명은 일반/고급/희귀/전설, 색은 은회색/청록/라벤더/창백한 금색. 보상 가중치는 100/45/15/3의 잠정값이다.
- 유물 6종은 에너지·손패·적중 피해·승리 후 회복. ID 중복 획득 불가, 다른 ID의 같은 효과는 합산.

## 수학과 출력

기존 `PrototypeCardCatalog`의 완성 그래프 18종·변환 4종은 수학 보관함이며 현재 시작 덱·보상에서 사용하지 않는다. 조립 입력은 u=x-5 또는 θ, 뒤의 연산을 순서대로 계산하여 y 또는 r을 만든다. 일반 곡선은 160개 선분의 같은 기하를 표시·명중에 사용한다. 화면 밖·정의되지 않은 값은 자르거나 제외한다. 수식을 화면에 맞추려고 임의 변형하지 않는다.

폴리오미노와 폴리노미오그래프는 다르다. 폴리노미오그래프는 이미지 텍스처가 아니라 **실제 수식의 선**이다. p(z)=z^n-1의 뉴턴 수렴, 64×48 필드, 근 경계와 반복 4/6/8/11/15/20의 등고선을 마칭 스퀘어로 만들며 최대 8,192개 선분 버퍼를 사용한다. GL 렌더러와 EquationAnalyzer가 같은 선분을 읽는다. 영역 이미지 공격으로 되돌리지 않는다.

작도는 중심 (5,0)에서 확장되는 반경으로 실제 선분을 공개한다. 얇은 전체 예측선은 남는다. 장식과 밝은 링은 판정에 참여하지 않는다. 기존 순차 공개 A/B 프로파일은 변경 전 비교 기록이다.

## 메모리·품질

- Update, OnGUI, 샘플링, 충돌 경로에서 LINQ·클로저·임시 컬렉션·문자열 조합을 만들지 않는다.
- 매 프레임 Instantiate/Destroy를 하지 않는다. 고정 배열과 재사용 버퍼를 우선한다.
- 새 할당은 소유 주체·수명·최대 용량을 ARCHITECTURE에 기록한다.
- 화면 문자열은 명령 후 갱신한다. 상태 문자열은 최대 8종, 툴팁 배열은 손패 용량이다.
- Core 규칙 변경에는 의미 있는 EditMode 회귀 테스트를 추가·갱신한다.
- 성능 개선은 Profiler로 검증한다. 이전 측정 수치를 새 전투 전체의 성능처럼 표현하지 않는다.

## 검증

2026-09-06: Unity EditMode 63/63 통과. `Logs/editmode-combat-v2-final.xml` 참조. Full HD 진단 캡처와 결과는 `Logs/CombatV2Captures`에 있다. 진단은 고정 손패·적 체력·게이지를 설치한 fixture로, 전체 런 밸런스 통과를 뜻하지 않는다.

Unity가 이 프로젝트를 열고 있으면 강제 종료하지 말고 Test Runner 또는 격리된 검증 복사본을 사용한다. `Logs/CombatV2VerificationProject`는 이번 검증을 위한 Assets/Packages/ProjectSettings 복사본이며 영구 소스의 기준이 아니다. 비교 후 실행하고 사용자 작업을 복사본으로 덮어쓰지 않는다.

과거 `Temp/GraphaclysmVerification`, `Temp/GraphaclysmEditModeHarness` 보조 프로젝트는 없다. Temp에 영구 소스를 복구하지 말고 Unity Test Runner를 사용한다. 자동 캡처는 `Graphaclysm.Editor.CombatV2Smoke.RunBatch`; 명시적인 batch 호출로만 실행한다. 실제 실행 명령은 PROTOTYPE을 따른다.
