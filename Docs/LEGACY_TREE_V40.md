# 잔광 성좌 — 사용자 이미지 기반 UI 개편

사용자가 제공한 문화 비교 화면에서 중앙의 큰 마름모, 작은 능력 심볼, 좌우로 이어지는 연결선, 어두운 배경과 청록색 연구 상태를 직접 확인하고 구성에 반영했다. 이전의 세 탭/상품형 목록을 없애고 기존14항목을 하나의 연결된 성좌로 표시한다. 원작 이미지를 게임 자산으로 복사하지 않고 기존 GUI 도형으로 그린다.

## 화면

중앙 무료 ‘기록의 핵’에서 기본 항목으로 이어지고, 기존에 실제 선행 조건이 있는 항목은 부모 노드에서 이어진다. 선행이 없는 항목 사이에 임의의 순서나 통행료를 추가하지 않는다. 예비 열쇠/발굴 분대는 여행 경비에서, 파편 감별은 유물 지참에서, 돌파/수호 분대는 작도 피해/시작 보호막에서 갈라진다.

14항목·총26단계와 기존 효과/비용을 유지한다. 화면에 모두 들어오도록 배치했으며 이번에는 추가 드래그나 축소 기능을 넣지 않았다. 노드에는 작은 심볼·짧은 기능명·현재 단계를 표시한다. 클릭하면 오른쪽에 효과, 선행 조건, 다음 비용이 고정된다. ‘다음 단계 습득’을 눌러 한 단계씩 구매하고 ‘선행 노드 보기’로 부모 설명을 확인한다. 호버만으로 상세창을 열지 않는다. 기존 분대 선택 화면과 전투/보상 규칙39는 그대로다.

## 요청한 투자 초기화

초기화 대상은 원정 성장점이 아니라 계정의 잔광 투자14항목이다. 각 단계에 실제 지불한 `기본 비용 + 당시 단계`를 합산해 전액 반환한다. 보유 잔광, 기존 종료 정산 기록, 현재 원정 스냅샷은 지우지 않는다. 분대 개방도 초기화되며 다시 투자해 개방할 수 있다.

영구 저장 v3를 초기화 완료 표시로 사용한다. 기존 v1/v2를 처음 적용할 때 후보 상태를 먼저 저장한 후에만 메모리에 환급을 적용한다. 실패하면 기존 기록과 단계는 유지하고 새 트리 구매를 차단한다. 다시 실행하여 재시도한다. 완료한 뒤 구매한 노드는 이후 실행에서 다시 초기화되지 않는다.

사용자 요청에 따른 현재 계정 초기화는 별도의 명시적 batch 진입점 `LegacyTreeReset.RunExplicitPlayerReset`으로 처리한다. `--reset-player-legacy-tree` 인수가 없으면 거부하며 Unity의 실제 데이터 경로가 `LocalLow/DefaultCompany/GRAPHACLYSM`과 일치하는지도 검사한다. 실행 전 `legacy.save.before-tree40` 복구 사본을 남긴다. 일반 테스트와 화면 캡처는 별도 데이터 디렉터리를 사용한다.

## 소유권과 검증

Application이 일회 초기화와 환급을 소유한다. View는 고정14좌표·이름·심볼과 설명 캐시만 소유하며 계정 변경은 기존 저장 우선 구매 API를 통한다. 문구는 잔광·선택 노드가 바뀔 때 갱신한다. 이미지 생성, 외부 게임 이미지 사용, 프레임별 컬렉션 생성은 없다.

최종 검사580/580 통과(`Logs/legacy40-tests.xml`). 기존 준비 화면 runner를 재사용한23장 검사에서 게임 런타임 오류0 (`Logs/legacy40-smoke.log`). 잔광 화면은 이제 탭이 아닌 성좌이며720p에서 전체 연결·노드명·선택 상세를 직접 확인했다. 원본/검증 사본 C# 차이0. 새 실행 파일·전체 원정 밸런스 검사는 별도다.

요청한 실제 계정 초기화 완료: 투자분52잔광 반환, 보유11→63잔광, 투자 단계 초기화. `legacy.save.before-tree40`에 원본 복구 사본을 남겼다. 실제 처리 결과는 `Logs/CombatV2VerificationProject/Logs/player-legacy-tree-reset.txt`. 원정 저장은 수정하지 않았다.
