# 1차 정리 · 연속 탑 지도까지

## 현재 기준

최근 사용자 요청과 실제 코드가 과거의 대규모 기획안보다 우선한다. 기존 문서의 미구현 제안과 구현된 기능을 혼동하지 않는다.

- 전투: 이안의 집행/기록, 루나의 조율/관측과 각 방식의 궁극기.
- 원정 성장: 방식별 16노드 트리. 시작 3점, 진행 중 최대 6점, 총 9점. 기술/궁극 각성의 배타 선택 유지.
- 원정 구조: 5층, 층마다 보스 후보 추첨. 방·보스의 실제 연결과 전투 데이터는 이번에 변경하지 않는다.
- 보상: 가로 카드형 전리품에서 원하는 것만 수령. 색별 파편 선택, 은화, 유물, 열쇠, 봉인 상자. 상점에도 카드/유물/파편 선택 상품.
- 영구 성장: 잔광 24노드 / 36단계, 분대 개방과 유물 지참 등. 기존 투자와 잔액을 보존.
- 이번 지도: 현재 층만 잘라 보여주던 화면을 전체 원정이 이어진 하나의 세로 탑으로 교체.

## 연속 탑 지도

`GraphaclysmTowerMapView`가 지도 표시/스크롤을 맡는다. 기존 `MapPoint`의 층 나머지 연산과 현재 층 필터를 없애고, 절대 Layer에 따라 방을 아래에서 위로 배치한다. 기존 NextNodeIndex로 그리므로 보스에서 다음 층까지 같은 경로가 이어진다. 원정 저장/계정 저장 버전은 각각 41/4 그대로다.

왼쪽 버튼 드래그, 마우스 휠, 세로 스크롤바를 지원한다. 현재 위치/꼭대기/입구 버튼을 제공한다. 이동은 보기만 바꾸며 미래 방을 해제하지 않는다. 방 진입은 기존 IsAvailable 및 TrySelectMapNode 검증을 유지한다. 드래그 후 MouseUp을 소비해 오입장을 막고, 모달이 열린 동안 지도 입력은 차단한다.

새 원정/이어하기 또는 완료한 방 수가 바뀌면 다음에 갈 수 있는 방으로 화면을 맞춘다. 단순 재그리기나 메뉴를 여닫을 때는 둘러보던 위치를 유지한다. 옛 3층 지도도 같은 배치 계산을 사용한다.

## 배경 방식

기존 탑 내부 그림을 층 구간의 재질로 재사용하고, 긴 수직 기둥·발판·층 경계·지붕·기단을 코드로 이어 그린다. 새 AI 배경 이미지를 생성한 것은 아니다. 배경 구조와 방은 같은 스크롤 값을 쓰므로 함께 움직인다. 지도 높이는 실제 LayerCount로 정하며 고정 화면 이미지를 늘어뜨리는 방식이 아니다. 중첩 GUI 그룹의 회전 선분 clipping 문제를 피하기 위해 선분과 이미지 영역을 직접 자른다.

## 소유권/메모리

지도 View가 노드 이름/보상 힌트 배열 2개(NodeCount 크기), 층 이름 배열 1개(FloorCount 크기)를 소유한다. 지도 인스턴스가 바뀔 때만 다시 만든다. 방 수가 늘어나도 화면 밖 요소는 표시하지 않고 선분은 viewport에서 자른다. 스크롤/드래그 상태는 View 수명이며 계정이나 명령 기록에 추가하지 않는다. 전투의 난수/덱/자원은 변경하지 않는다.

## 검증 범위와 이후

최종 결과: EditMode **583/583** (`Logs/tower42-tests.xml`), 지도 화면 **12장 / 게임 Runtime 오류 0** (`Logs/tower42-smoke.log`). 층 경계와 정상의 1080p/720p 화면을 직접 확인했다. 층 제목을 연결선보다 앞에 그리도록 보완하고 재검증했다. 원본/검증 사본 C# 해시 차이 0. 사용자 계정/원정 저장과 실행 중 Editor는 보존했다.

화면에서 발견한 도입 안내의 과거 성장점 +2/+3 문구도 현재 전리품 원정에서 제거했다. 실제 성장점 지급량이나 이전 원정 규칙은 바꾸지 않았다.

전체 EditMode 회귀와 별도 탑 지도 화면 검사를 사용한다. 화면 검사는 모든 층 경계, 입구/정상, 1080p/720p, 드래그 해제/휠/경계 제한/모달 차단, 실제 첫 전투 승리 뒤 복귀, 저장 재생, 이전 지도 표시를 확인한다. 검증 사본과 임시 저장만 사용한다.

현재 범위 밖: 전체 5층 수동 밸런스 테스트, 실행 파일 최종 빌드, 모든 기존 UI의 전면 정리. 다음 기능 방향은 사용자의 후속 정리를 받은 뒤 결정한다. 오래된 제안 목록을 자동으로 이어서 구현하지 않는다.
